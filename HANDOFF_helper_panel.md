## PART A — Per-deal helper chat panel in the Company OS dashboard

### Objective
Inside each lead's detail view, add a collapsible in-window chat panel: a helper
agent scoped to that ONE collaboration. The user opens a lead (atypica, PaXini,
AZ8), expands the panel, pastes emails, and chats to get walked through that
specific deal. It runs entirely on the local Mac Studio LLM (no cloud API, no cost).

### Feature spec
1. A collapsible side panel WITHIN the same detail view — expands to a full-height chat
   column beside the deal, collapses to a handle/tab. NOT a floating mini-window, NOT a
   popup. One window.
2. Standard chat UI: message list, input box, send. Show a "thinking" state while
   `window.claude.complete` is in flight (local model is slower than cloud; expect
   several seconds per reply, longer on a cold call).
3. Per-deal scoping: on open, seed the model with THIS lead's context — company, contact,
   stage, rate, deliverable, and the email history on the card. The helper answers about
   this deal specifically.
4. Paste-in: the input accepts long pasted email text; it is sent as the user turn with
   the deal context still in scope.
5. Per-deal memory: persist each lead's chat thread so it survives reload, keyed by card
   id. Prefer a new nullable `helper_thread jsonb` column on `cards` (add via SQL migration
   in `ops/sql/`); if that is out of scope, fall back to `localStorage` keyed by card id.
   One deal's conversation must never bleed into another.
6. On-policy behavior: prepend a fixed system preamble with the business rules so replies
   come out compliant: payment in full and upfront (no partial / 50-50 splits); the
   Robert-then-Asher two-email reply flow; subject format `{NAME or COMPANY} x SCOBLE x COLLAB`;
   and NO hyphens or em dashes in drafted content. Put this preamble in one editable constant
   at the top of the feature.

## PART B — Switch the local model from qwen3.6:35b-a3b to qwen2.5:32b-instruct

### Why
The current `qwen3.6:35b-a3b` is a *reasoning* model — it needs `think:false` /
`/no_think` hacks and still sometimes returns empty output. For drafting, summarizing,
and JSON classification, a non-reasoning INSTRUCT model is more reliable and drafts
better. `qwen2.5:32b-instruct` (q4 ~20GB) fits the 48GB Mac Studio with headroom.

Tradeoff to expect: qwen3.6:35b-a3b is a mixture-of-experts model (~3B active per token,
so fast). qwen2.5:32b-instruct is DENSE (all 32B active), so it is SLOWER per response.
Batch jobs (8am scraper) won't notice; interactive drafting will feel a few seconds
longer. Quality and output reliability go UP. This is the accepted trade.

### The model name lives in ONE shared place plus TWO hardcoded lists
1. **`local_llm.py` (repo root), line ~16** — the shared client used by the browser
   bridge (`window.claude.complete`) AND every Python pipeline:
   ```
   LOCAL_MODEL = os.environ.get("LOCAL_MODEL", "qwen3.6:35b-a3b")
   ```
   Change the default to `"qwen2.5:32b-instruct"`. This one edit covers the bridge and
   all importers unless a `LOCAL_MODEL` env var overrides it.
2. **`scripts/active/google_docs_brief_server.py`, lines ~72-76** — the brief server keeps
   its own preference lists that hardcode the model. Update BOTH:
   - the dict entry `{"base_url": "http://127.0.0.1:11434/v1", "model": "qwen3.6:35b-a3b", ...}`
   - the tuple `("http://127.0.0.1:11434/v1", "qwen3.6:35b-a3b")` in `PREFERRED_LOCAL_MODELS`
   Change `qwen3.6:35b-a3b` -> `qwen2.5:32b-instruct` in both. (Leave the separate
   `hermes-agent` @ :8642 entries alone unless that backend is also being retired.)
3. **Deal Tracker** (`scripts/active/deal_tracker.py`) reads `DEAL_MODEL_NAME`
   (default `qwen3.6:35b-a3b`). Set `DEAL_MODEL_NAME=qwen2.5:32b-instruct` in its
   env / launchd, or update the default.

### Steps (run on the Mac Studio)
1. Pull the model: `ollama pull qwen2.5:32b-instruct`
2. Make the three code changes above.
3. Restart the affected launchd agents:
   ```
   launchctl kickstart -k gui/$(id -u)/com.unaligned.local-llm-bridge
   launchctl kickstart -k gui/$(id -u)/com.unaligned.google-docs-brief-server
   ```
   (The daily scraper picks up `local_llm.py` on its next run.)
4. Verify the bridge reports the new model:
   `curl -s http://127.0.0.1:8787/health` -> should show `"model":"qwen2.5:32b-instruct"`.

### Cleanup (optional but recommended)
Because qwen2.5-instruct is NOT a reasoning model, the reasoning workarounds are dead
weight and the `/no_think` suffix can leak as stray text. In the callers, drop:
- the `"think": False` payload flag,
- the `/no_think` appended to user prompts,
- the reasoning-field fallback (`msg.get("reasoning")`) — plain `content` is now reliable.
Search the pipelines (`deal_tracker.py`, `local_llm.py`, brief server) for `no_think`,
`think`, and `reasoning` to find them.

### Rollback
Keep `qwen3.6:35b-a3b` installed in Ollama. To revert, set `LOCAL_MODEL=qwen3.6:35b-a3b`
(and the brief/deal values back) and restart the two agents. One-line switch back.
